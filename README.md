# LMS Lite

Учебная платформа (Learning Management System) с REST API для создания курсов, прохождения уроков, тестирования студентов и выдачи сертификатов.

## Стек

- Java 21, Spring Boot 3, Maven
- Spring Web, Spring Data JPA, Hibernate, Jakarta Bean Validation
- PostgreSQL, Lombok
- Docker, Docker Compose

## Запуск через Docker (рекомендуемый)

**Необходимо:** Docker Desktop / Docker Engine и Docker Compose.

1. Создайте в корне проекта файл `.env` (не добавляйте его в Git):

   ```dotenv
   POSTGRES_DB=lms_db
   POSTGRES_USER=lms_user
   POSTGRES_PASSWORD=replace_with_local_password
   ```

2. Из корня проекта выполните:

   ```bash
   docker compose up --build
   ```

3. После успешного запуска API доступен на `http://localhost:8080`.

   Проверка:

   ```bash
   curl http://localhost:8080/api/courses
   ```

Полезные команды:

```bash
docker compose ps
docker compose logs -f app
docker compose down
```

В `docker-compose.yml` настроены сервисы `app` и `db`, переменные окружения для подключения к PostgreSQL, `healthcheck` базы и `depends_on` с ожиданием её готовности. Данные БД хранятся в Docker volume и сохраняются при штатной остановке/перезапуске контейнеров. **Не выполняйте `docker compose down -v`, если необходимо сохранить данные.**

> Пароль в `.env` — пример локальной конфигурации. Для реального развёртывания используйте надёжный пароль и защищённое хранение секретов.

## Локальный запуск без Docker

**Необходимо:** JDK 21, Maven и работающая PostgreSQL.

1. Создайте БД `lms_db` и пользователя PostgreSQL с доступом к ней.
2. Установите переменные окружения. Пример для PowerShell:

   ```powershell
   $env:DB_URL="jdbc:postgresql://localhost:5432/lms_db"
   $env:DB_USERNAME="lms_user"
   $env:DB_PASSWORD="your_local_password"
   ```

3. Проверьте версию JDK и соберите проект:

   ```powershell
   java -version
   mvn clean verify
   ```

4. Запустите приложение:

   ```powershell
   mvn spring-boot:run
   ```

Адрес API: `http://localhost:8080`. Настройки приложения находятся в `src/main/resources/application.yml` и используют переменные `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`.

## Реализованные этапы основного задания

1. **Модели и ORM.** Студенты, преподаватели, курсы, уроки, вопросы, записи на курсы, прогресс и сертификаты. Уроки типов `VIDEO`, `TEXT`, `QUIZ` хранятся с наследованием `SINGLE_TABLE` и дискриминатором.
2. **Репозитории и сервисы.** Spring Data JPA; операции с сущностями и бизнес-ограничения в сервисном слое.
3. **REST API.** Регистрация студента и преподавателя; CRUD курсов и уроков; публикация и архивирование курсов; просмотр списка курсов и деталей.
4. **Обучение.** Запись только на опубликованные курсы, запрет повторной записи, отметка пройденных уроков, подсчёт прогресса и автоматическое завершение записи при 100%.
5. **Тесты и сертификаты.** Вопросы тестов без раскрытия правильных ответов, проверка результата, выдача уникального сертификата по завершении курса, проверка по UUID и скачивание текстового `.txt`-сертификата.
6. **Валидация и ошибки.** Bean Validation и обработка исключений с понятными HTTP-статусами и JSON-ответами.
7. **Контейнеризация.** Multi-stage Dockerfile (Maven + Java 21 JRE), Docker Compose с PostgreSQL, ожидание готовности БД, отдельный volume.

### Примеры API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/instructors` | Регистрация преподавателя |
| POST | `/api/students` | Регистрация студента |
| POST | `/api/courses` | Создание курса |
| GET | `/api/courses` | Опубликованные курсы |
| GET | `/api/courses/{id}` | Детали курса |
| PATCH | `/api/courses/{id}/publish` | Публикация курса |
| POST | `/api/courses/{courseId}/lessons` | Создание урока |
| POST | `/api/enrollments` | Запись студента |
| GET | `/api/enrollments/{id}/progress` | Прогресс |
| POST | `/api/enrollments/{id}/lessons/{lessonId}/complete` | Завершение обычного урока |
| GET | `/api/lessons/{quizId}/questions` | Вопросы теста |
| POST | `/api/lessons/{quizId}/submit?enrollmentId={id}` | Сдача теста |
| GET | `/api/students/{id}/certificates` | Сертификаты студента |
| GET | `/api/certificates/{code}` | Проверка сертификата |
| GET | `/api/certificates/{id}/download` | Скачивание сертификата (`text/plain`) |

## Принятые допущения

- Это учебный MVP: **аутентификация и разграничение доступа не реализованы**. Идентификаторы передаются в запросах; сервис не следует публиковать в открытый интернет без защиты.
- Курс доступен для записи только после перехода в `PUBLISHED`.
- Для пары студент–курс повторная запись запрещена, включая случай ранее прекращённой записи (`DROPPED`).
- `VIDEO` и `TEXT` отмечаются пройденными вызовом API; `QUIZ` требует успешной сдачи.
- Для теста сохраняется оценка в прогрессе, но отдельная полная история попыток не ведётся.
- Сертификат создаётся один раз для пары студент–курс после завершения обучения; файл формируется при запросе, а не хранится на диске.
- Для учебной БД включено `spring.jpa.hibernate.ddl-auto=update`; миграции Flyway/Liquibase не настраивались.
- Видеоуроки представлены URL: загрузка и хранение видеофайлов не реализованы.

## Не реализованные дополнительные задания

Следующие **дополнительные**, не входящие в реализованный MVP возможности не выполнены:

1. **PDF-сертификаты:** скачивание реализовано в `.txt`, генерации PDF нет.
2. **Экспорт данных в CSV/JSON:** отсутствуют `/api/courses/{id}/export` и выгрузка списка студентов курса.
3. **Импорт вопросов из JSON:** отсутствует загрузка файла через `multipart/form-data`.
4. **Фоновые задачи `@Scheduled`:** нет ежедневных напоминаний и еженедельной автоархивации.
5. **Статистика курсов:** нет агрегированной статистики курсов, топа курсов и статистики преподавателей.
6. **Рейтинг и отзывы:** нет отзывов, рейтинга и распределения оценок.
7. **Изменение порядка уроков:** нет пакетного `/api/courses/{courseId}/lessons/reorder`.
8. **Результаты всех тестов:** нет `/api/enrollments/{id}/quiz-results` с количеством и временем всех попыток.
9. **Полный набор автоматических тестов:** не реализованы требуемые дополнительные unit-тесты EnrollmentService и QuizService на JUnit 5/Mockito; выполнялся контекстный Spring Boot тест и ручные проверки API.
10. **Swagger/OpenAPI:** интерактивная документация Swagger UI не добавлена; для проверки используются прямые REST-запросы/Postman.

## Проверка проекта

- `mvn clean verify` выполнялся с **JDK 21** в Maven-контейнере: `BUILD SUCCESS` после исправления расположения тестового класса.
- В тестовом Docker Compose окружении PostgreSQL имела статус `healthy`, а приложение запускалось; `GET /api/courses` возвращал `HTTP 200`.
- Проверено создание таблиц `students`, `instructors`, `courses`, `lessons`, `questions` и других; в `lessons` имеется дискриминатор `dtype`.
- Через Postman вручную проверены основной сценарий обучения (курсы, три типа уроков, запись, тесты, прогресс, сертификаты), негативные сценарии и дополнительные CRUD-запросы.
- Проверка сохранности данных после перезапуска и запуска процесса Java без root фиксируется отдельно по результатам соответствующих команд; успешное прохождение этих проверок здесь не утверждается.

## Ограничения

Приложение предназначено для демонстрации бизнес-логики LMS и локального запуска. Для production потребуются аутентификация/авторизация, полноценные автоматизированные тесты, управление схемой БД через миграции, хранение секретов и мониторинг.
